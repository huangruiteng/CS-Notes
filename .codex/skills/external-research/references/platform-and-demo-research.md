# Platform and demo research

Read this for X discovery, interaction design, or Agent-product research.
Use the platform's currently available search behavior; examples below are query
ideas, not assumptions about a permanent API or an exhaustive checklist.

## X: discover, then trace to the creator

For a user request to use Ego Lite, begin with an actual browser action through
`ego-browser`. Its skill owns TaskSpace reuse, navigation, login/user-control
handling and cleanup. Read it instead of guessing methods or probing profiles.
Use the inherited login when available. If access is blocked, report the actual
boundary; do not claim to have searched X via a different surface. An authorized
fallback may yield useful leads, but label that route honestly.

Useful query pivots for Agent interfaces:

- `("multi-agent" OR "agent team") ("interface" OR "dashboard") filter:videos`
- `"agent" "mission control" filter:videos`
- `"agents" "canvas" filter:videos`
- `from:<creator> <product or feature>` after discovering a credible origin.

Start with the user's language, then add synonyms or another language when it
helps coverage. Use creator filters, exact phrases or selective exclusions when
results are noisy. A high-like post is a discovery lead, not stronger evidence.
A product name such as “Mission Control” is ambiguous: keep the creator and
original URL with the finding.

Inspect the original post and author follow-ups when they supply attribution,
source code or a live demo. Do not convert quoted marketing into verified product
behavior. A useful announcement can lead to documentation or implementation
inspection if feasibility matters; do not install or run an unknown project just
to substantiate a visual observation.

Search and read authorization does not authorize follows, likes, reposts, replies,
bookmarks, subscriptions, installs or account changes. Avoid these incidental
mutations while inspecting posts. Keep unrelated feed/account details out of the
research record.

## Inspect the interaction, not just its poster

Choose the cheapest observation that answers the question. DOM text is useful for
features and controls; screenshots establish composition; video or live interaction
is needed for motion, transitions and changing context.

For a video, identify the useful segment instead of sampling only the opening
logo or thumbnail. Observe an actual transition or seek to relevant moments using
available controls. Note if only selected frames were inspected. Loading a poster
or seeing a play button is not watching the demonstrated journey.

Inspect a live product read-only when available and relevant; do not require
signup or paid execution for every design study. Ask: what caused the change,
what stayed stable, where did context go, and can the user get back? A promotional
cut, scripted playback and real interactive behavior have different evidential
strength. Keep local screenshots as supporting notes when useful, but do not
publish unrelated account chrome or copy proprietary artwork into the product.

## Agent-specific relevance

Distinguish these mechanisms before selecting references:

| Mechanism | What to inspect | Common overclaim |
| --- | --- | --- |
| Spatial presence / office / RTS | Member identity, selection, location meaning, access to work | Moving characters prove useful work or collaboration |
| Shared artifact canvas | Contributor attribution, partial outputs, comparison, handoff | Several panels prove agents adopted each other's work |
| Execution scene / activity stream | Sessions versus tools, actual event source, history and recovery | Tool success proves accepted outcome |
| Agent/Git activity graph | What nodes and edges encode, timestamps, stable context | Commit volume proves task or research progress |
| Dispatch / review console | Assignment, blockers, review, feedback and next action | More controls make a better first screen |

For a research-agent team, look for the path from question to evidence, independent
challenge, correction and synthesis. A generic agent interface can supply only
part of that path; identify the missing part rather than pretending the reference
solves the whole journey. Other tasks should use their own outcome chain.

Separate expressive craft from operational semantics. Spatial depth, materials,
motion and composition can delight; attach status meaning only where the system
actually supplies that fact. Do not categorically ban playful styles, prescribe
one color scheme, or turn a user's rejection of one prototype into a universal
rule. Use the current task’s evidence to decide which visual mechanisms improve understanding.

## Practice-derived failure repairs

- **Broad visual drift:** a search for Agent collaboration finds attractive sites
  built by AI. Repair the query around operating agents and the user's workflow;
  retain general visual inspiration only as secondary material if still useful.
- **Technology substitution:** library docs replace product/interaction research.
  Inspect concrete experiences, then use official docs to assess implementation.
- **Repost accumulation:** many summaries repeat one creator. Trace the origin,
  compare an independently useful reference, and keep source-family lineage.
- **Poster-only inspection:** claims about animation come from a static frame.
  Inspect the relevant segment or downgrade the claim to a composition observation.
- **Link collection without application:** the report grows but the design does
  not change. Map the strongest mechanisms to a concrete design or validation step.
